# Smart Home Energy Management System

## Overview

The Smart Home Energy Management System is a full-stack web application for monitoring household appliance usage, estimating energy costs, handling appliance faults, and supporting role-based energy management workflows.

The project was developed for software engineering coursework and demonstrates a Django REST Framework backend connected to a React and Vite frontend. It supports three main user roles: homeowner, administrator, and technician.

## Key Features

### Homeowner

- Register and log in as a homeowner.
- View a personalised energy dashboard.
- Add, update, delete, and monitor home appliances.
- Record appliance energy usage.
- View appliance usage sessions and daily billing information.
- Receive high-usage and appliance fault notifications.
- View and manage energy-saving recommendations.

### Administrator

- View system-wide dashboard summaries.
- Manage user profile information, membership status, and plan details.
- Create, update, and remove pricing plans.
- Use the electricity cost calculator.
- View all homeowner appliances in read-only mode.
- Review appliance category reports.
- Monitor fault reports and system notifications.

### Technician

- View technician dashboard summaries.
- Monitor appliances in read-only mode.
- View fault alerts.
- Mark fault reports as completed.
- Reset appliance status to `ok` after maintenance.

## Architecture

The application is separated into a backend API and frontend client.

- The backend exposes REST API endpoints for authentication, users, appliances, energy usage, pricing, notifications, recommendations, and dashboards.
- The frontend consumes the API and provides role-based pages for homeowners, administrators, and technicians.
- The completed frontend can also be built and served through Django for a single-server demonstration.

## Design Patterns Used

| Pattern | File | Purpose |
| --- | --- | --- |
| Factory | `backend/appliances/factory.py` | Creates default appliance data based on appliance type. |
| Observer | `backend/notifications/observers.py` | Creates notifications when high usage or faults occur. |
| Strategy | `backend/pricing/strategies.py` | Supports different electricity cost calculation methods. |
| Singleton | `backend/dashboard/energy_manager.py` | Centralises dashboard aggregation logic. |

## Setup Instructions

### Backend Setup

From the project root:

```bash
cd backend
python -m venv venv
```

Activate the virtual environment.

Windows:

```bash
venv\Scripts\activate
```

macOS/Linux:

```bash
source venv/bin/activate
```

Install dependencies and prepare the database:

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py setup_real_credentials
python manage.py seed_homeowner_data
```

Run the backend server:

```bash
python manage.py runserver
```

The backend runs at:

```text
http://127.0.0.1:8000/
```

Demo account credentials are generated by the setup command and should be supplied separately for assessment or demonstration use.

### Frontend Setup

Open a second terminal from the project root:

```bash
cd frontend
npm install
npm run dev
```

The frontend development server runs at:

```text
http://localhost:5173
```

## Single-Server Demonstration

The React frontend can be built and served by Django.

Build the frontend:

```bash
cd frontend
npm install
npm run build
```

Start Django:

```bash
cd ../backend
python manage.py runserver
```

Open:

```text
http://127.0.0.1:8000/
```

## Main API Endpoints

| Endpoint | Method | Description |
| --- | --- | --- |
| `/api/login/` | POST | User login |
| `/api/register-homeowner/` | POST | Homeowner registration |
| `/api/change-password/` | POST | Password change |
| `/api/user-profiles/` | GET, PATCH | User profile management |
| `/api/appliances/` | GET, POST | Appliance listing and creation |
| `/api/appliances/<id>/` | PATCH, DELETE | Appliance update and deletion |
| `/api/appliance-schedules/` | GET, POST | Appliance schedules |
| `/api/fault-reports/` | GET, POST | Fault report listing and creation |
| `/api/fault-reports/<id>/mark-done/` | PATCH | Mark a fault report as completed |
| `/api/energy-usage/` | GET, POST | Energy usage records |
| `/api/energy-usage-sessions/` | GET | Appliance usage sessions |
| `/api/daily-bills/` | GET | Daily bill records |
| `/api/pricing-plans/` | GET, POST, PATCH, DELETE | Pricing plan management |
| `/api/calculate-cost/` | POST | Strategy-based cost calculation |
| `/api/notifications/` | GET, DELETE | Notification listing and deletion |
| `/api/notifications/<id>/mark-read/` | PATCH | Mark a notification as read |
| `/api/recommendations/` | GET, POST, DELETE | Energy-saving recommendations |
| `/api/dashboard-summary/<homeowner_id>/` | GET | Homeowner dashboard summary |
| `/api/admin-dashboard-summary/` | GET | Administrator dashboard summary |

## Testing

The project has been checked with:

```bash
python manage.py check
npm run build
```

Manual testing was completed for:

- Login and role-based navigation.
- Homeowner registration.
- Appliance creation, updates, deletion, and monitoring.
- Energy usage recording.
- Billing and usage session views.
- Pricing plan management and cost calculation.
- Notifications and recommendation workflows.
- Fault reporting and technician completion workflow.
- Admin dashboard, reports, and read-only monitoring pages.
- Django-served React build.

## Limitations

- The authentication approach is suitable for coursework demonstration but not production deployment.
- SQLite and Django development settings are used.
- Testing is mainly manual and should be expanded with automated tests.
- Real-time notifications are not implemented.
- The application is designed for local demonstration rather than cloud deployment.
